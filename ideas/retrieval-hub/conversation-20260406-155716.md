# Conversation — 2026-04-06

First ideation session for retrieval-hub. Started from an empty repo with only `docs/PLATFORM_COMPONENT_PATTERN.md` (the shape inherited from memory-hub) in place.

## What the user brought

A pretty fully-formed pitch:

- A platform component on OpenShift AI, modeled on memory-hub but for **retrieval** instead of memory.
- Retrieval **sources show up as cards** like the RHOAI model catalog. Each card represents a dataset or data connection that's already optimized for RAG.
- Examples: a chunked-and-ingested document corpus in a vector or graph DB; a tabular dataset with a retrieval surface for filter/aggregate; medical or scientific corpora with domain-aware ingestion.
- Each card carries: embedding model, RAG recipe (chunking, overlap, embedding size, etc.), sample agent system prompts, performance evals across LLMs, possibly per-LLM or per-LLM-family prompts.
- **MCP tools** for agents: get, put, query, query rewrite, etc.
- **Per-dataset query rewriting** as an opt-in capability. Agent submits a raw question, gets back a knowledge-set-specific set of better-formed questions. Can use the agent's own LLM or one on the cluster. Captures the user intent better than any raw query would.
- Ingestion as an enterprise-managed concern, with data managed at an enterprise level.

## What I went and looked up

Did a fast pass on GitHub + market. The single most important thing I found:

**Red Hat is already building this category inside OpenShift AI 3.** The "AI Hub / gen AI Studio" ships an "AI Assets" catalog, and the public roadmap explicitly calls out "knowledge sources for RAG" as a planned future asset type alongside MCP servers. That's not "similar" — that's the same idea, from the platform owner.

This isn't a blocker. It's a positioning question: are we (a) the reference implementation that fills that slot, (b) a complementary component that registers itself as one or more AI Assets, or (c) something more opinionated that lives alongside? See `open-questions.md` — this is the most important early decision and I want to put it back to the user.

Other notable finds:
- **RAGFlow** is the closest existing OSS, worth real evaluation
- **RAGExplorer** (PacificVis 2026) is doing the eval-comparison surface very well — exactly what each card should expose
- **RAG-MCP** paper formalizes per-dataset retrieval routing, validates the query-rewriter angle
- **SDG Hub** is a likely upstream for the eval-results portion of each card
- The "rewrite prompt as a property of the source, curated by the source owner" angle does seem genuinely under-explored — most people put rewriting in the agent

## What I want to ask the user next

The four questions I think are highest-leverage for the next round:

1. **Positioning vs. AI Hub / AI Assets** — pick one of the three options or tell me a fourth.
2. **Memory-hub boundary** — is `put` a real MCP operation here, or is retrieval-hub strictly read-for-agents with all writes through ingestion?

4. **Query-rewriter LLM default** — caller-supplied, cluster-resident, or both with a documented default?
